## 五、顺带复核：第三次推送的 `[R24c 观测]`（同一 run 原始行）

```
# [R24c 观测] linux  已退出 pid=4302 kill(pid,0) errno=ESRCH
# [R24c 观测] linux  pid=1（无权 open）kill(pid,0) errno=EPERM
# [R24c 观测] darwin 已退出 pid=3417 kill(pid,0) errno=ESRCH
# [R24c 观测] darwin pid=1（无权 open）kill(pid,0) errno=EPERM
# [R24c 观测] win32  已退出 pid=2464 kill(pid,0) errno=ESRCH
# [R24c 观测] win32  pid=4（无权 open）kill(pid,0) errno=EPERM
```

结论与批次六一致、再次复现：真 Windows runner 上「活着但无权 open」的进程报 **EPERM**（不是 EACCES），因此 libuv「Windows access denied → EACCES」这一映射在本项目 CI 上**仍未被观测到**；`EACCES` 分支只有注入用例覆盖。「只有 ESRCH 算已死」的规则对 EPERM/EACCES/其它 errno 一律保守判活，故两种映射下都安全。

## 六、判读口径与如实说明

1. **「真绿」的界定**：同一次 run、三腿各自 `fail 0` 且结论 success。本次满足；构建/发布作业按设计 `skipped`（未推 tag），不参与「测试真绿」的判定，也不代表安装包已在三平台构建成功。
